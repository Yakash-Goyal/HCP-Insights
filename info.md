# Project Info: HCP Insights & Segmentation Dashboard

## Summary
A data analytics project that identifies and segments high-value healthcare
providers (HCPs / physicians) based on their industry payment history, using
SQL for profiling and Python (RFM scoring) for prioritization — the kind of
analysis life-sciences commercial teams use to plan physician engagement and
KOL (Key Opinion Leader) targeting.

## Resume bullet (for reference)
> **HCP Insights & Segmentation Dashboard**
> Key Skills: SQL, Python (Pandas), Power BI, RFM Segmentation, Data Cleaning
> Analyzed CMS Open Payments public healthcare data to identify and segment
> high-value physicians for targeted engagement. Wrote SQL queries to profile
> physician-payment records by specialty, region, and payment volume, and
> built an RFM-style scoring model in Python to rank HCPs by recency,
> frequency, and value of industry engagement. Designed a Power BI dashboard

## Why this project
Life-sciences commercial analytics teams (the kind of work firms like
ProcDNA do for pharma clients) regularly need to answer: "which physicians
should we prioritize for outreach?" This project simulates that workflow
end-to-end using a publicly documented data schema (CMS Open Payments),
without requiring access to any real client or proprietary data.

## Dataset
- **Real-world basis:** [CMS Open Payments](https://openpaymentsdata.cms.gov/) —
  a US government dataset tracking payments pharma/device companies make to
  physicians (consulting fees, speaker fees, meals, research, royalties).
- **This repo uses a synthetic sample** (`data/sample_payments.csv`,
  generated by `generate_sample_data.py`) built to the same schema, so the
  project runs immediately without a large download. Swapping in a real CMS
  export requires no code changes — only the file.
- Sample size: 500 physicians, ~4,000 payment records, across 8 specialties
  and 10 US states.

## Methodology

### 1. SQL profiling (`sql/hcp_analysis.sql`)
- Aggregates total and average payment volume by specialty and by state
- Breaks down spend by payment type (consulting, speaker fees, etc.)
- Surfaces top 20 physicians by total payment value
- Checks concentration of spend across paying companies

### 2. RFM segmentation (`notebooks/rfm_segmentation.py`)
Classic RFM (Recency, Frequency, Value) scoring, adapted from retail
customer analytics to physician engagement:
- **Recency** — days since the physician's last payment (more recent = higher priority)
- **Frequency** — number of payments received
- **Value** — total dollar value of payments received

Each metric is scored into quartiles (1–4), summed into a combined RFM
score (3–12), and bucketed into three segments:
- **High Priority** (score 9–12)
- **Medium Priority** (score 6–8)
- **Low Priority** (score 3–5)

On the sample dataset, this produced: 186 High Priority, 199 Medium
Priority, and 114 Low Priority physicians.

### 3. Dashboard (Power BI)
Built from `output/hcp_segments.csv`:
- Segment distribution (High/Medium/Low priority counts)
- Drill-down by specialty and by state
- Top physicians table, filterable by segment
- Regional engagement gap view (states with high payment volume but few
  High Priority physicians — potential white space)

## Tech stack
- **SQL** — data profiling and aggregation
- **Python** (pandas, numpy) — RFM scoring logic
- **Power BI** — dashboard and visualization
- **CSV** as the interchange format between each stage

## Limitations / honest notes
- The dataset used here is synthetic, generated to mirror CMS Open
  Payments' schema and realistic payment distributions (log-normal amounts,
  skewed like real spend data) — not real physician data.
- RFM quartile-based scoring is a simple, interpretable segmentation method;
  a production version might use clustering (e.g., k-means) for more nuanced
  segments.
- This project simulates a commercial analytics workflow — it does not
  reflect any real client engagement or proprietary methodology.

## Possible extensions
- Swap in the real CMS Open Payments dataset (filterable by year/state on
  their site) for an authentic version
- Add a time-series view of payment trends per specialty
- Try k-means clustering as an alternative to quartile-based RFM scoring
- Add a simple "engagement gap" score combining payment volume with
  physician density per state
